- El evento pull_request hacia main (o push a main) dispara `.github/workflows/backend-ci.yml`: runner Ubuntu, PostgreSQL 16 aislado, pruebas Python del exportador, Node/Python del gateway, restore, build Release, suite .NET excluyendo el caso de carga y un paso separado de carga POS/WhatsApp. Sin concurrency en main. Un commit nuevo al mismo PR no cancela la ejecución anterior.
- `.github/workflows/remote-orders-checks.yml` ya limita concurrencia por ref y cancela ejecuciones reemplazadas. No se modifica: grupo distinto. Los workflows de recuperación son manuales, con otro grupo, y no se ejecutaron.

  Los intervalos de metadatos run_started_at/updated_at de las tres se superponen 4 min 43 s. No equivale a minutos facturados ni prueba que todos los pasos ejecutaran simultáneamente todo ese intervalo.
- Este feature no pasa por pantallas, HTTP, SignalR, handlers, EF/RLS o PostgreSQL productivo. Las suites sí cubren comportamientos de aplicación; no se modifican ni se suprimen. No cambia autorización, permisos de workflow, secretos, endpoints, SQL, caché, contratos, dinero o tracking.
- Docs de GitHub: https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#concurrency. Grupo por workflow/PR y run ID independiente para pushes a main; cancel-in-progress restringido a PR.
