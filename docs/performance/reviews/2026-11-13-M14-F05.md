## 1. Recorrido y causa raíz

1. En `src/components/branches/BranchPrintSettingsForm.vue`, el botón **Regenerar token** llama a `onRotateClick`; antes del cambio esperaba `confirmDialog()` **sin** poner `rotating.value = true`. El `BaseButton` se deshabilita solo cuando recibe `loading=true`. Mientras el diálogo sigue pendiente, varios clics pueden encolar confirmaciones.
2. Cada confirmación verdadera llama a `branchApi.rotateBranchAgentToken`: **POST** `/api/Branches/{branchId}/print-settings/rotate-agent-token`, sin deduplicación en cliente.
3. `SenorArroz.API/Controllers/BranchPrintSettingsController.cs` verifica roles/sucursal, invoca `RotateBranchAgentTokenCommand`, vuelve a consultar la configuración y publica `NotifyConfigChangedAsync` por SignalR.
4. `SenorArroz.Application/Features/BranchPrintSettings/Commands/RotateBranchAgentTokenHandler.cs` lee una fila de `BranchPrintSettings` por sucursal mediante EF Core, genera nuevo token y salt, calcula hash, cambia fecha y llama a `SaveChangesAsync` en PostgreSQL. Cada POST válido invalida el hash previo. El agente usa ese token localmente en `PrintJobsClient` y SignalR; otro POST puede invalidar el token que ya recibió el administrador.
5. **Defecto confirmado leyendo código:** la protección UI comienza tarde (después del `await`), con una ventana de confirmaciones superpuestas. No se afirma haber observado incidentes productivos. No se encontraron cambios previos en curso para este **subflujo**; los PR abiertos [Print Agent #2](https://github.com/savelasquezs/senorArrozPrintAgent/pull/2), [#3](https://github.com/savelasquezs/senorArrozPrintAgent/pull/3) y [Vue #72](https://github.com/savelasquezs/senorArrozFront/pull/72) cubren otras operaciones de impresión.

Revisión transversal: no hay lectura N+1 relacionada con esta acción; la operación consulta la configuración por sucursal y persiste un registro. No se ha validado EXPLAIN/índices, porque no se requiere nueva consulta ni cambio de esquema. El coste del cálculo criptográfico, HTTP, SignalR y SQL de cada petición duplicada es real por estructura del flujo, pero no tiene medición de CPU/RAM/latencias/egress.
