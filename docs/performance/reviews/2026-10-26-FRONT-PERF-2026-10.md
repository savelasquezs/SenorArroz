## Flujo y cambios API

1. **Opciones de domiciliario en pedidos.** `GET /api/orders/deliveryman-options` proyecta ID/nombre distintos con el contexto del buscador, fechas Colombia y origen remoto autorizado. Sustituye el barrido de páginas de pedidos para construir un selector. La búsqueda principal propaga cancelación hasta MediatR/EF.
2. **Historial WhatsApp.** `GET /api/whatsapp/conversations/{id}/messages/page` entrega 50 mensajes por defecto, máximo 100, cursor opaco timestamp/ID y orden ascendente de presentación. Conserva autorización operativa y reparación de URLs solo para la página devuelta. Leer una página anterior no borra mensajes nuevos sin leer. El endpoint anterior permanece disponible.
3. **Mapa de domiciliarios.** `GET /api/deliverymen/map` proyecta únicamente los campos utilizados por el mapa, pagina hasta 200 pedidos del día y agrupa las últimas ubicaciones de ese día en la primera página. Evita solicitudes HTTP por empleado y conserva la sucursal/tenant autorizados. Vue preserva ubicaciones SignalR más recientes que el snapshot HTTP.
4. **Disponibilidad POS.** La consulta opcional `forOrderCreation=true` valida rol de gestión y sede activa del tenant del usuario antes de cruzar el catálogo compartido con los saldos de la sede operativa del borrador. El servicio y endpoint mantienen la modalidad administrativa anterior. Vue limita las tandas a 100 productos y conserva como pendiente el stock estricto sin confirmar.

Se integraron localmente las mejoras existentes de contexto operativo de sucursal, reservas, lectura de clientes y cancelación de gastos: API 62/64/68/70 y frontend 42/44/46. Los PR remotos no se fusionaron ni publicaron desde este programa.
