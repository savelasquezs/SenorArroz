## 1. Flujo y causa raíz

- **Pantalla:** `senorArrozFront/src/views/DeliveryTrackingIncidentsView.vue` abre evidencia/reproducción bajo demanda; `deliveryTrackingIncidentsApi.getPlayback(filters, signal)` hace GET `/api/delivery-tracking/playback` con domiciliario(s), rango y sucursal. Hay generación y `AbortSignal` para descartar pantallas obsoletas. No requiere cambios Vue.
- **Endpoint / EF:** `SenorArroz.API/Controllers/DeliveryTrackingPlaybackController.cs::Get` valida rango (hasta 24 h), IDs positivos, existencia, rol y sucursal. Consulta `DeliverymanLocations` del rango con máximo 20.000 puntos, eventos, permanencias, sesiones, rutas, stops y contexto para trazar la ubicación. No se identificó N+1 por domiciliario en ese recorrido: las consultas se hacen por conjuntos de IDs.
- **Defecto confirmado:** para determinar si cada permanencia es la última de su sesión, el endpoint ejecutaba `DeliverymanLocations.Where(WorkSessionId IN sessionIds).Select(id,workSessionId,recordedAt).ToListAsync()`, **sin límite temporal**. Después agrupaba y ordenaba *todas* las filas en memoria para obtener un solo ID por sesión y ejecutaba otro SELECT por IDs para obtener `TrackingMode`. Esta hidratación no estaba protegida por el límite de 20.000 de la búsqueda de puntos de reproducción y genera transferencia, asignaciones y trabajo de ordenamiento en la API.
- **Cambio:** calcular último punto por sesión en el servidor SQL con `GroupBy(workSessionId)` y `OrderByDescending(recordedAt).ThenByDescending(id).First()`, proyectando también el modo. No se necesitan todos los registros históricos ni el segundo GET a la tabla.
- **Índices existentes (inspección EF/scripts):** `idx_dloc_work_session`, `idx_dloc_work_session_id`, `idx_dloc_deliveryman_recorded_id`. No se propone un índice nuevo especulativo sin EXPLAIN en una muestra representativa. RLS multitenant, roles, permisos, conteo de reproducción, orden de coordenadas y contratos se mantienen sin cambios.
- **Interacciones externas:** Flutter es productor de ubicaciones; SignalR no interviene en este GET; Next.js y agente de impresión no usan este controlador. Ninguno se modifica. Otros PR de M41-F01 (#142/#143), M41-F02 (#137/#138) y M41-F03 (#135/#136) permanecen separados.
