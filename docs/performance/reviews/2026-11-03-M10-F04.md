## 1. Flujo y causa raíz

`OrdersList.vue` / `OrderDetailContent.vue` → `EditCustomerModal.vue` → `customersStore.fetchById(id)` → `customerApi.getCustomerById` → `GET /api/customers/{id}` → `CustomersController.GetCustomer` → `GetCustomerByIdHandler` → `CustomerRepository.GetByIdWithAddressesAsync` (EF Core `AsNoTracking`, `AsSplitQuery` e `Include` de sucursal, teléfonos, direcciones, barrio y cobertura por sucursal). El handler también obtiene estadísticas agregadas y previsualizaciones de fidelidad. `CustomerDto.Addresses` es una `List<CustomerAddressDto>` inicializada como lista vacía; el payload completo incluye `addresses: []` cuando no hay direcciones.

Antes de esta corrección, al terminar `fetchById`, el modal llamaba **siempre** a `hydrateCustomerWithAddresses(c)`. Esta función invoca `customersStore.fetchAddresses(id)` → `GET /api/customers/{id}/addresses` → `GetCustomerAddressesHandler` → repositorio de direcciones. El segundo GET y trabajo SQL se repiten incluso si el detalle ya incluye direcciones y coberturas. No hay evidencia de N+1 SQL dentro de una consulta; son dos solicitudes HTTP del flujo. La secuencia de carga inicial no invalidaba respuestas si se seleccionaba otro cliente o se cerraba el modal; una respuesta tardía podía sustituir el perfil mostrado.

**Detalle importante:** las fichas elegidas en `CustomerSection` pueden provenir de búsquedas resumidas. Su `addresses: []` no garantiza que se haya consultado el detalle completo. Se conserva la carga explícita de direcciones para clientes seleccionados desde búsqueda; únicamente se reutiliza `addresses` de la petición de detalle por ID.

**Dependencias:** no intervienen SignalR, Flutter, Next.js ni Print Agent en esta corrección. El backend y sus endpoints permanecen sin cambios; no se alteran consultas de cotización, pagos, stock, ventas ni notificaciones. `OrdersController.UpdateOrder` → `UpdateOrderHandler` → `OrderRepository` sigue siendo el camino para guardar el pedido y queda fuera del diff. No se ha consultado `EXPLAIN` ni validado índices en PostgreSQL.

**PRs anteriores y conflictos:** se revisaron los PR abiertos del frontend. El PR #56 toca `OrderDetailContent.vue` y sus pruebas, pero no `EditCustomerModal.vue` ni `EditCustomerModal.deliveryFee.test.ts`. Los PR #42, #44, #46, #55, #57, #58, #61 y #62 tampoco tocan esos dos archivos. Comprobar de nuevo al fusionar.
