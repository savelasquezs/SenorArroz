## 1. Flujo y causa raíz

`components/cart/CartDrawer.tsx` → `requestQuote`, selección de beneficio o revalidación antes de confirmar → `lib/api.ts.requestDeliveryQuote` → `POST /api/storefront/delivery-quote` (Next.js) → `app/api/storefront/delivery-quote/route.ts` → `POST /api/public/storefront/delivery-quote` → `PublicStorefrontController.Quote` → `StorefrontCommerceService.QuoteCore` → validaciones/concurrencia/caché de geocodificación → consultas EF Core (direcciones, sucursales, horarios, productos, cobertura) y `GetValidRoutes` (Google Routes) → PostgreSQL y proveedor externo.

La pantalla ya incrementaba un contador de generación para **ignorar resultados tardíos**. Sin embargo, al cambiar carrito/formulario/sucursal o cerrar el panel, las llamadas previamente emitidas continuaban: `lib/api.ts` no pasaba `AbortSignal`, y el proxy Next.js siempre creaba exclusivamente `AbortSignal.timeout(20_000)`. Una cancelación del navegador no llegaba al proxy ascendente. Por eso el backend podía seguir consumiendo tiempo y recursos aunque el cliente ya no necesitara esa respuesta. Se corrige la causa en los tres eslabones sin ampliar reglas financieras.

El backend ya acepta `CancellationToken` en `PublicStorefrontController.Quote` y lo pasa a `QuoteCore`. `QuoteCore` lo propaga al control de concurrencia, lecturas EF Core, validación de dirección y cálculo de rutas. **No se modifica backend.**

**Datos de código comprobados:** debounce de 250 ms para cambios con cotización previa, descarte por `quoteRequestRef`, límite de 20 s del proxy, token en API. `QuoteCore` también puede actualizar `address_branch` al crear relación para una dirección guardada; la cancelación no revierte escrituras ya comprometidas.

**No confirmados:** número real de HTTP simultáneos por caja/usuario, SQL exacto por interacción, índices utilizados, tasas de cache-hit y comportamiento de cancelación de Google tras despacho. En este feature no existe acoplamiento directo con SignalR, Flutter, POS Vue, Print Agent o workers. Los PR abiertos del 30-oct corrigen M15/M17, sin solapamiento de archivos con esta rama; Next.js no tenía PR abiertos en el momento de selección.

## 3. Corrección mínima en rama

- `lib/api.ts`: `requestDeliveryQuote(body, signal?)` pasa la señal a `fetch`; firma compatible con consumidores anteriores.
- `lib/quote-abort-scope.ts`: ámbito único para abortar la cotización anterior, invalidar al cambiar estado/cerrar panel y liberar únicamente su propio controlador. No administra el POST de pedido.
- `components/cart/CartDrawer.tsx`: usa ámbito de abort para cotización normal, beneficio y preconfirmación. Conserva control de generación, previene resultados/errores obsoletos, cancela al revisar carrito/dirección, cerrar o desmontar. **La creación de pedido y Wompi siguen sin cancelación y con idempotencia original.**
- `app/api/storefront/delivery-quote/route.ts`: une `request.signal` y el timeout máximo de 20 s mediante `AbortSignal.any`, pasando la señal combinada a la petición hacia API.
- Tres archivos nuevos de pruebas: `quote-abort-scope.test.ts`, `quote-transport.test.ts`, `quote-proxy-cancellation.test.ts`. Verifican cancelación de la solicitud anterior, liberación segura, propagación navegador→Next y Next→API.

**Riesgo y compatibilidad:** una cancelación HTTP es best-effort: una operación ya completada o una llamada externa despachada puede generar consumo. Los errores de cancelación no se muestran como errores de cotización. `AbortSignal.any` requiere Node 20.3+, compatible con el runtime de CI configurado. El proxy conserva el límite de duración. Sin cambios de esquema, contratos financieros, autorización, pagos o datos persistidos.

**Verificaciones ejecutadas y bloqueo confirmado:** [Storefront CI #41204258806](https://github.com/savelasquezs/senor-arroz-web-nextjs/actions/runs/41204258806) terminó en FAILURE tras **dos intentos de menos de cinco segundos cada uno sin ningún paso ejecutado** (`steps=[]`; no hubo checkout, TypeScript ni Vitest). El mismo repositorio tuvo fallo igualmente sin pasos en su `main` el 31-oct ([run #41179592887](https://github.com/savelasquezs/senor-arroz-web-nextjs/actions/runs/41179592887)), por lo que no se atribuye automáticamente el fallo al diff. La recuperación de logs reportó `BlobNotFound`. **La causa exacta del fallo de arranque no está identificada y la CI del cambio de código NO está validada.** El PR web #15 permanece en borrador.

Se realizó comprobación sintética local **separada**, sin dependencias Next.js: `createQuoteAbortScope` compiló con TypeScript estricto y siete aserciones de Node pasaron; se verificó propagación de `AbortSignal.any` al cancelar la señal de entrada. No equivale a ejecución de las seis pruebas Vitest preparadas, ni del build Next.js. El contenedor carece de acceso de red para instalar dependencias o clonar este repositorio.
